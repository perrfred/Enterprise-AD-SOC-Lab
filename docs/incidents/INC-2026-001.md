# INC-2026-001 — Suspected Brute-Force Authentication Attempt

## Incident Summary

A controlled authentication attack was simulated against the `Alice.Martin` domain account from workstation `WS-01`.

Five consecutive failed authentication attempts were generated within approximately 25 seconds. The account lockout policy triggered successfully, generating Windows Security Event ID 4740 on the domain controller.

The investigation found no evidence of a successful authentication for `Alice.Martin` during the attack window.

The account was disabled as a containment measure, its password was reset, and the account was subsequently re-enabled after recovery verification.

## Detection

The incident was detected through repeated Windows Security Event ID 4625 records on `WS-01`.

Five failed authentication attempts targeting `Alice.Martin` were observed:

| Time | Event |
|---|---|
| 18:36:05 | 4625 — Failed logon |
| 18:36:11 | 4625 — Failed logon |
| 18:36:17 | 4625 — Failed logon |
| 18:36:26 | 4625 — Failed logon |
| 18:36:30 | 4625 — Failed logon |

The repeated failures triggered the configured domain account lockout threshold.

---

## Account Lockout

At approximately 18:36:30, AD-DC01 generated Windows Security Event ID 4740.

The event identified:

- Locked account: `alice.martin`
- Caller computer: `WS-01`
- Domain: `FREDDYS`

This established the relationship between the authentication failures observed on `WS-01` and the resulting account lockout recorded by the domain controller.

---

## Scope Analysis

A review of Event ID 4625 records between 18:30 and 18:40 identified:

| Account | Failed Attempts |
|---|---:|
| Alice.Martin | 5 |

No other accounts were identified as targets during the investigation window.

The incident was therefore assessed as limited in scope to a single user account.

---

## Authentication Success Check

Event ID 4624 records were reviewed on AD-DC01 for `Alice.Martin` between 18:30 and 18:40.

**Result:** No successful logon (Event ID 4624) was found for `Alice.Martin` during the investigation window.

This indicates that the investigation found no evidence of successful authentication during the simulated attack.

---

## Containment

The affected account was disabled using Active Directory administrative controls.

Verification confirmed:

```text
alice.martin    False```

The account was therefore prevented from authenticating while the investigation and remediation activities were performed.

---

## Credential Remediation

The password for `Alice.Martin` was reset using Active Directory administrative controls.

The previous password was not retained or documented.

---

## Recovery

After containment and password remediation, the account was re-enabled.

Final account state:

SamAccountName    Enabled    LockedOut
--------------    -------    ---------
alice.martin      True       False

A post-recovery review of WS-01 found no new Event ID 4625 failed-logon events for the account after midnight on September 6, 2026.

## Root Cause Assessment

The activity was a controlled simulation of repeated authentication failures against a domain account.

The observed behavior is consistent with a brute-force or password-guessing pattern.

Because the activity was intentionally generated as part of the SOC lab, there is no evidence of an external attacker or real-world compromise.

---

## Severity Assessment

**Medium**

The incident was classified as Medium because:

- Repeated authentication failures were detected.
- An account was successfully locked by the security control.
- The activity affected a domain account.
- No successful authentication was identified.
- No evidence of malware or broader system compromise was identified.
- The observed scope was limited to one account and one workstation.

---

## Response Effectiveness

The security controls operated as intended:

1. Failed authentication attempts were logged.
2. Repeated failures were detectable through Windows Event Logs.
3. The domain account lockout policy prevented continued authentication attempts.
4. The affected account was identified.
5. The account was disabled as an additional containment measure.
6. Credentials were reset.
7. The account was restored after remediation.
8. Post-recovery monitoring showed no new failed authentication events.

---

## Final Disposition

**Closed — No Evidence of Successful Compromise**

The investigation determined that the simulated authentication attack was successfully contained by the environment's authentication and account-lockout controls.

No evidence of successful authentication or broader compromise was identified during the investigation.
